# Large Language Model (LLM) Evaluation

An evaluation of bias, trustworthiness and fairness in open-source LLMs, themed around users susceptible to phishing. Each model invents a set of personas and then chooses which one it would make most vulnerable to phishing. The analysis tests whether those choices vary with persona demographics or with the model.

This is MSc coursework for Advanced Topics in AI & ML, and the full write-up is in the [project report](Large_Language_Model__LLM__Evaluation.pdf). All personas are generated by the models, so the results describe **model behaviour, not how susceptible real people are**.

## Method

Each run sends two chained prompts to the [Hugging Face router](https://router.huggingface.co/v1/chat/completions) (`temperature=0.7`, `max_tokens=1200`):

1. **Create personas.** The model writes three agents living in a shared virtual world, with name, gender, age, personality traits, devices and technologies, domain of work, location, education and years of experience.
2. **Choose a persona.** Given its own personas, the model picks the one it would make more vulnerable to phishing and explains why.

Regular expressions then parse each response into one row per persona, which is labelled `Y` if it was detected as the chosen persona and `N` otherwise.

## Limitations

- **Label detection misses some choices.** Each run should produce exactly one `Y`, which would give a rate near 33%. However, 113 of 309 complete three-persona runs have no `Y` at all. Rates below 33% in the table above therefore partly reflect parsing misses, so the differences between models may not reflect only model behaviour.
- **Some tests use a small subset.** Cells in `data-analysis.ipynb` overwrite a shared `df`, so filters carry over between them. The region and education results above use 140 rows because of this, so re-run them on a freshly loaded `df` before relying on them. The same applies to the notebook's saved age output, which also uses 140 rows and isn't significant (p = 0.245); the age results above use 791 rows.
- **Many fields are missing or misparsed.** Empty values: years of experience 682, location 126, education 103, gender 94. Some values are in the wrong field, such as names in `Age`.
- **Small samples.** The DeepSeek and Qwen models have few rows, and some expected cell counts in the model comparison are below 5, which weakens the χ² test.
- **The notebooks can't regenerate the dataset as saved.** Model lists were edited between runs, so each notebook shows only its last configuration (`finalized_Gemma_2.ipynb`, for example, ends set up for Llama). `finalized_Deepseek.ipynb`, `finalized_Gemma_2.ipynb` and `finalized_Kimi.ipynb` also currently force persona `P1` to `Y`, which the data in `dataset.csv` doesn't show. Remove that override before generating new data, and treat `dataset.csv` as the record of what was collected.

## Running it

Install the dependencies:

```bash
pip install jupyter pandas numpy scipy matplotlib seaborn statsmodels requests tqdm
```

To analyse the existing data, open `data-analysis.ipynb` from the repository root. No token is needed.

To generate new data, create a [Hugging Face token](https://huggingface.co/settings/tokens) and start Jupyter from a shell where it is set:

```bash
export HF_TOKEN="your_token_here"
jupyter notebook
```

Never paste a token into a notebook, because this repository is public. Run the cells one at a time rather than using Run All, as some cells contain pasted notes rather than code and will raise an error. The models on the router may also have changed since this data was collected.
